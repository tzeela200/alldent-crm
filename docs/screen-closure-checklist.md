# Screen Closure Checklist — מתי מסך נחשב "סגור"

מסמך DoD אחיד להרצה על **כל מסך** במערכת ALLDENT לפני שמכריזים עליו כמוכן.
מסך נחשב "סגור" רק כשעברת על כל הפריטים, הרצת את הפעולות בפועל, וראית את השינוי
אמיתי ב-Supabase (לפני ואחרי). לא "נראה עובד" — **אומת בראיות**.

מקרא סימון: ✅ אומת תקין · ⚠️ אומת עם פער · ❌ אומת כשבור · ❓ טרם נבדק.

---

## 1. נתונים 📊
- [ ] **מקור חי** — המסך קורא מ-Supabase, לא ממוק/hardcoded.
- [ ] **מילונים מ-SSOT** — סטטוסים/תפקידים/אזורים מגיעים מ-`dict_*` החי, לא מרשימה מקומית.
- [ ] **קריאה גלובלית** — חיפוש/סינון עובדים על *כל* הנתונים, לא רק על מה שנטען לעמוד.
- [ ] **מספרים מדויקים** — כל מונה/KPI סופר בדיוק את מה שהלחיצה עליו מציגה (הספירה = הפילטר).

## 2. פעולות (כתיבה) ✍️
- [ ] **כל כפתור עובד** — מחובר ל-handler אמיתי, אין כפתור מדומה/מת.
- [ ] **שמירה באמת נשמרת** — כל פעולה כותבת ל-DB (לא רק state מקומי + טוסט).
- [ ] **אימות כתיבה** — הצלחה מוצגת רק אחרי שווידאנו שהשורה עודכנה (rowcount), לא רק "אין error".
- [ ] **אטומיות** — פעולה עם כמה כתיבות (למשל יצירת מועמד+קישור) מצליחה או נכשלת ביחד.
- [ ] **מניעת כפילות** — לא ניתן ליצור רשומה כפולה; בדיקה לפני insert.

## 3. מצבי מסך (UI states) 🪟
- [ ] **פאנל/דיאלוג** — נפתח, נסגר, טוען, מציג נתונים נכונים.
- [ ] **יצירה** — שדות חובה נאכפים, נשמר נכון, נפתח מה שנוצר.
- [ ] **עריכה** — עריכה נשמרת; כשל שמירה לא סוגר עריכה ולא מאבד טקסט.
- [ ] **טעינה / ריק / שגיאה** — שלושה מצבים נפרדים; שגיאה מציגה שגיאה (לא "אין נתונים").

## 4. עקביות מערכת 🔗
- [ ] **קישורים תקינים** — כל ניווט מוביל ל-route אמיתי (`/admin/...`), לא 404/אתר ציבורי.
- [ ] **חוקים עסקיים** — מעברי סטטוס, הגדרת "פעיל/סגור", והשפעות חוצות-ישויות (השמה→משרה) תואמים למודל המאושר.
- [ ] **סנכרון בין מסכים** — אחרי שמירה, כל המסכים התלויים מתרעננים (מועמדים/360/דשבורד).
- [ ] **רכיבים משותפים** — שימוש חוזר ברכיבי הדיזיין-סיסטם (RoleBadge/RegionBadge/SortableTh/AdminTable/דרופדאון), לא מימוש מקומי כפול.

## 5. איכות וגמר ✅
- [ ] **הרשאות/RLS** — גישה מתאימה לתפקיד (לא כל `authenticated` עושה הכל).
- [ ] **נייד / RTL / עברית-first** — רספונסיבי, כיוון נכון, בלי טקסטים באנגלית שנשארו.
- [ ] **אימות ריצה אמיתי** — להריץ בדפדפן, לבצע כל פעולה, לבדוק Console/Network, ולוודא ב-Supabase שהנתון השתנה לפני ואחרי.

### נדחה בכוונה (דורש אישור/החלטה נפרדת — לא נגעתי כדי לא להכניס באג)
- **סינון גלובלי + `total`** — הפילטרים `job_status`/`work_status`/`availability` על שדות מועשרים; דורש View/RPC או ארכיטקטורה, לא תיקון מהיר.

- **השמה→עדכון משרה** — כפתור אישור ידני (החלטה: לא אוטומטי) — טרם מומש.

- **הפרדת הרשאות/RLS** — כרגע כל authenticated = CRUD מלא; החלטה עסקית + שינוי Supabase.
- **אימות ריצה בדפדפן** — דורש סשן מחובר (Auth).
